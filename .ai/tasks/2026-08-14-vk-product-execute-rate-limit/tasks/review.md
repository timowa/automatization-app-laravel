# Review: Рефакторинг CreateVkProductJob — execute и rate limit

## Что проверить

### Rate limit
- Подсчитать количество API-запросов при выполнении CreateVkProductJob для 11 групп
- Убедиться, что общее количество запросов не превышает 3 в секунду
- Проверить паузы между чанками execute (если групп > 25)

### execute (VKScript)
- Проверить корректность генерации VKScript кода
- Экранирование строковых значений (name, description) — могут содержать кавычки
- Лимит 25 вызовов в одном execute — проверить разбивку на чанки
- Проверить обработку результатов execute (success/failure для каждой группы)

### Устаревшие методы
- Убедиться, что photos.getMarketUploadServer больше не вызывается
- Убедиться, что photos.saveMarketPhoto больше не вызывается
- Проверить, что замена (wall-фото или без фото) работает с market.add

### Идемпотентность
- Проверить, что при частичном выполнении execute (часть товаров создана, часть нет)
  сохраняются только успешные результаты
- Проверить, что повторный запуск job не создаёт дубликаты товаров

## Какие файлы проверить

- `app/Services/Vk/VkApiService.php` — новые методы, корректность VKScript
- `app/Jobs/CreateVkProductJob.php` — логика загрузки фото один раз
- `app/Jobs/EditVkProductJob.php` — использование execute
- `app/Jobs/ArchiveVkProductJob.php` — единый execute для всех случаев
- `tests/` — покрытие тестами

## Ожидаемое поведение

### CreateVkProductJob для 11 групп
1. Фото загружается ОДИН раз (3 API-запроса: getWallUploadServer + upload + saveWallPhoto)
2. market.add для всех 11 групп — 1 execute (1 API-запрос)
3. Итого: 4 API-запроса (вместо 44+)
4. Время выполнения: ~2-3 секунды
5. Все успешные результаты сохраняются в vk_products

### EditVkProductJob для товаров в 11 группах
1. market.edit для всех 11 товаров — 1 execute (1 API-запрос)
2. Итого: 1 API-запрос (вместо 11+)

### ArchiveVkProductJob для товаров в разных группах
1. market.delete для всех товаров — 1 execute (1 API-запрос)
2. Не зависит от количества групп

## Потенциальные риски

1. **Экранирование в VKScript** — name и description могут содержать кавычки, спецсимволы.
   Если не экранировать — VKScript сломается. Проверить json_encode для строк.

2. **market.add без market-фото** — если photos.getWallUploadServer + photos.saveWallPhoto
   не работают с market.add (photo_id от wall-фото), товары будут без фото.
   Проверить visually или через тестовый запуск.

3. **Параллельные jobs** — TaskDispatcher dispatch-ит все pending задачи одновременно.
   Если одновременно выполняются CreateVkPostJob, CreateVkRepostJob, CreateVkCommentJob,
   CreateVkProductJob — они могут вместе превысить лимит. Это не решается в данной задаче,
   но нужно отметить как известный риск.

4. **Большие описания** — description товара может быть длинным. Проверить лимиты VKScript
   на длину кода.

## Сценарии тестирования

1. Создание товаров в 11 группах — проверить что все 11 товаров созданы, нет "Too many requests"
2. Создание товаров в 30 группах — проверить разбивку на 2 execute (25 + 5) с паузой
3. Редактирование товаров в 11 группах — один execute
4. Архивация товаров в разных группах — один execute
5. Создание товара с фото — фото загружается один раз, используется во всех группах
6. Создание товара без фото — main_photo_id=null, не должно падать
7. Частичный сбой execute — 5 из 11 товаров созданы, 6 с ошибкой — сохранить только 5
8. Спецсимволы в name/description — кавычки, переводы строк не ломают VKScript
