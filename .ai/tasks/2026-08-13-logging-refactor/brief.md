# Рефакторинг системы логирования

## Описание задачи

Три проблемы в текущей системе логирования:

### Проблема 1: Иерархия логов

Все лог-файлы создаются в одной плоской директории `storage/logs/`. Нужно создать иерархию: для VK-каналов — отдельные поддиректории по шаблону `storage/logs/vk/<channel>/error-YYYY-MM-DD.log`. Короткие сообщения об успехе/неудаче — в головной лог `job`. Детальные ошибки и warning задач — в соответствующие поддиректории.

### Проблема 2: Дублирование ошибок по каналам

Все ошибки приложения одновременно записываются во все каналы логирования. Файлы `job-2026-08-13.log`, `vk-2026-08-13.log`, `vkRepost-2026-08-13.log`, `stats-2026-08-13.log`, `check_tokens-2026-08-13.log`, `vk-sync-2026-08-13.log`, `laravel-2026-08-13.log` — идентичны по содержимому.

Причина: `LOG_STACK=single,daily,vk,vkRepost,vk-sync,check_tokens,stats,job,debug` в `.env` — stack-канал по умолчанию (`LOG_CHANNEL=stack`) пишет во все каналы из стека одновременно. Приложение вызывает `Log::channel('job')->info(...)`, но необработанные исключения Laravel идут через default channel (stack) и дублируются везде.

Требование: ошибки приложения должны писаться только в `laravel.log`. Специфичные каналы — только записи, явно записанные через `Log::channel('channel_name')`.

### Проблема 3: Permission denied при записи логов

В `laravel.log` зафиксирована ошибка:
```
The stream or file "/var/www/html/storage/logs/laravel-2026-08-13.log" could not be opened in append mode: Failed to open stream: Permission denied
```

Ошибка возникает при запросе к `POST /offer`. Пользователь отправил тестовый вебхук, получил ошибку записи лога.

Контекст Docker:
- PHP-FPM работает от пользователя `www-data` (UID 33) внутри контейнера.
- Лог-файлы на хосте принадлежат `timowa` (Windows UID), внутри контейнера монтируются как есть.
- Текущие файлы логов имеют права `644` и владельца `timowa` — `www-data` не может писать в них (нет прав на запись для group/others).
- Объём `laravel.log` — 12 МБ, 760+ записей "Permission denied" — ошибка каскадно размножается (попытка залогировать ошибку логирования тоже падает).

## Требования

1. Иерархия логов: `storage/logs/vk/<channel>/error-YYYY-MM-DD.log` для VK-каналов.
2. Канал `job` — только info/warning (успех/неудача задач), без детальных ошибок.
3. VK-каналы — только error/warning (детальные ошибки задач).
4. Ошибки приложения (необработанные исключения) — только в `laravel.log`, не дублируются в остальные каналы.
5. Исправить проблему прав доступа на лог-файлы в Docker-окружении.
6. Удалить несуществующий `debug` канал из `LOG_STACK`.
