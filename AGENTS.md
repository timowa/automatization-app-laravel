# AGENTS.md

## Общее описание

Проект — автоматизация публикации объектов недвижимости для одного агентства.
Получает данные об объектах через вебхук, сохраняет в MySQL, а затем публикует контент на страницу агента во ВКонтакте: посты на стене, истории, репосты.

## Стек технологий

- PHP 8.4 
- Laravel 13.24
- MySQL 8.x
- Composer
- VK PHP SDK `vkcom/vk-php-sdk: ^5.131`
- Intervention Image `intervention/image: ^4.1`

## Правила кода
- Всегда реализовывать принцип единой ответственности
- Использовать типизацию свойств и параметров
- Файлы PHP совпадают с именем класса
- Имя сценария совпадает с именем директории
- Не оставлять `dd()`, `var_dump()` и `die()` в production-коде. Для отладки использовать логи.
- Именование:
- - Классы — `PascalCase`
- - Методы и свойства — `camelCase`
- - Константы — `UPPER_SNAKE_CASE`
- - Файлы PHP — совпадают с именем класса

## Архитектура
- Контроллеры отвечают только за HTTP: Получение запроса, формирования ответа
- API: Для апи реализован единственный endpoint /offer, для которого отключена проверка CSRF токена. Ответ API должен быть максимально быстрым, поэтому 
  после получения запроса, валидации и сохранения использовать event и dispatch job
- Работа с БД: Для выборки использовать класс DB. К Eloquent прибегать только, если нужно подгружать зависимости и связи

### Работа с VK API

- Токены агентов хранятся в таблице vk_users. Никогда не логировать токены и не выводить их в открытый доступ.
- При ошибках VK API (captcha, rate limit, revoked token) логировать и сохранять флаг/статус, не паниковать.
- Публикации должны быть идемпотентными: проверять дубли перед созданием постов/историй.
- **Rate limit VK API: не больше 3 запросов в секунду.**
- **Запросы, которые можно сгруппировать для одного агента (например, репост в несколько групп), обязательно объединять в один вызов метода `execute()` с кодом на VKScript.**
- VKScript — строго типизированное подмножество TypeScript. Поддерживает базовые операции, циклы, условия, работу с массивами и вызовы API-методов.
- При реализации методов, использующих `vkcom/vk-php-sdk`, отталкиваться от официальной документации: https://dev.vk.com/ru/method.
- Генерация баннеров историй и загрузка медиа — через Intervention Image + `stories.get`/`photos.getWallUploadServer` и связанные методы загрузки.

## Логирование
- Использовать Log::channel() для логирования. Под каждый тип задачи реализован свой канал логирования. В канал логирования задачи пишется только warning и 
  error. Основной канал логирования - job. В нем должны храниться логи в следующем порядке:
- - Запрос получен
- - Оффер создан
- - Публикация и задачи созданы
- - Лог info об успешном выполнении задачи. Например "Пост по офферу 14 создан. ['post_id': 'wall_241645*']". Либо лог warning об ошибке, не указывая саму 
    ошибку. Сама ошибка будет отображена в соответствующем канале лога. Например "Ошибка создания поста по офферу 15"

## Процесс автоматизации

```
Вебхук (POST /offer) массив offers
    ↓
Парсинг переданных параметров в DTO, валидация на повтор, сохранение в бд
    ↓
Event OfferCreatedEvent
    ↓
Определение измененных полей в оффере (OfferChanged)
    ↓
Определение сценария на основе предыдущего оффера, нового и изменений (ScenarioResolver)
    ↓
Создание транзакции на добавление публикации по новому офферу и заданий, присущих выбранному сценарию
    ↓
Выполнение независимых задач сценария
    ↓
Выполнение зависимых задач сценария
```
## Offer
Снимок поступившего запроса по 1 объекту.
По одному объекту может быть создано несколько запись Offer.
Уникальность объекта определяется полем offers.code

## Agent
Список агентов. К агенту привязаны токены доступа ВК. Offer связывается с агентом по agent_id в таблице offers. Для получения id агента выполняется поиск по 
номеру телефона (agents.phone) из запроса.

## Publication
Хранит информацию о публикации по конкретному Offer и выбранному сценарию.
Публикация в контексте проекта несет смысл набора действий, которое приложение должно сделать при том или ином сценарии. Это может быть создание нового 
поста \ истории \ комментария \ репоста, редактирование или удаление существующего.

## PublicationTask
Хранит информацию о задаче, которую нужно выполнить для публикации. Статус задачи (enum PublicationTaskStatus), Тип задачи (enum PublicationTaskType), От 
какой задачи зависит (dependent_on_id)

Задачи делятся на два типа: 
- Независимые: могут быть выполнены в любой момент
- Зависимые: могут быть выполнены, только если задача, от которой зависит в статусе success
Например: Создать пост в ВК (PublicationTaskType::VK_POST) - независимая. Добавить к посту комментарий (PublicationTaskType::VK_COMMENT) - зависимая - чтобы 
  добавить коментарий к посту, нужно, чтобы пост был создан.

Зависимости задач прописаны в App/Helpers/PublicationTaskDependenceInspector.php

Независимые задачи добавляются в таблицу publication_tasks в статусе pending
Зависимые задачи добавляются в таблицу publication_tasks в статусе Waiting

Когда независимая задача переходит в статус success запускается App/Helpers/PublicationTaskDependencyResolver.php, чтобы зависимые от нее задачи перешли в 
статус 
pending

## Задачи
Типы задач - App/Enums/PublicationTaskType.php
Статусы задач - App/Enums/PublicationTaskStatus.php
Резолвер задач решает какую Job должна выполнить задача по типу - App/Helpers/JobResolver.php
Jobs - App/Jobs

## Описание задач
- VK_POST - Создать пост на личной странице агента
- VK_REPOST - Сделать репост созданного поста с личной страницы агента в группы, id которых сохранены в таблице vk_groups и пользователь имеет в них право 
- редактора
- VK_STORY - Создать историю на личной странице пользователя с ссылкой на созданный пост
- VK_LOOP_STORY - Создать историю на личной странице пользователя с ссылкой на созданный пост, публиковать эту историю раз в 3 дня
- VK_END_LOOP_STORY - Перестать публиковать историю раз в 3 дня
- VK_COMMENT - Создать комментарий под созданным постом
- VK_CREATE_PRODUCT - Создать товар в группе, сохранить информацию о созданном товаре в формате agent_id, group_id, product_id, чтобы можно было 
  отредактировать либо архивировать товар
- VK_EDIT_PRODUCT - Отредактировать созданный товар в группе
- VK_ARCHIVE_PRODUCT - Архивировать созданный товар в группе

### ScenarioRule
Правила выполнения сценария. 
У всех сценариев есть одно общее правило (кроме "Анонс" и "Продажа"): Сценарий выполняется, только если была публикация со статусом ниже. Статусы сценариев 
определяются порядком в App/Scenario/ScenarioFactory.php
Остальные правила создаются для каждого сценария. Правило считается выполненным, если метод passes вернул true.
Сценарий считается выбранным, если по всем правилам не было false
