# Отчёт по журналам прода

По команде сразу выполнить одну команду `node scripts/collect-prod-logs.mjs` и ответить по её JSON. Код приложения, MCP и сервер не менять. Сырые файлы отдельно не скачивать и `summarize_prod_logs` не вызывать. Пароли, токены и фамилии не писать. Не читать `access.local.md` и `.cursor/mcp.json`.

Цель: убрать из журналов те `WARNING` и выше, за которыми программа ведёт себя неверно или падает. Внешний отказ, который код уже обрабатывает верно, в промпт кода не входит. Имена людей и номера из журнала в ответ не входят.

Готового списка сбоев нет. Каждую группу разобрать заново по полям JSONL и по коду.

## Вызов

Один запуск на запрос. Повтор с тем же интервалом не делать.

| Как сказано | Аргумент |
|---|---|
| без срока | аргументов нет: последние 24 часа |
| последние N минут | `--minutes=N` |
| последние N часов | `--hours=N` |
| дата | `--date=YYYY-MM-DD`, сутки по Москве |
| явный интервал | `--from` и `--to`, ISO 8601, UTC |

Если в stdout есть поле `error`, остановиться и передать этот текст. Другой способ забора журнала не искать.

## Что читать

`collected.files` — канал, `json_lines`, `text_lines`. `collected.missing_files` — файла нет. `collected.download_errors` — скачивание сорвалось, файл может существовать. Такой канал отсутствующим не называть, отчёт назвать неполным.

`query` — ответ сборщика. Разбирать `groups`: `fingerprint`, `event_name`, `exception_class`, `level`, `message`, `count`, `first_seen`, `last_seen`, до двух `samples` (`file`, `line`, `operation`, `context`, `stack_trace` у первого). Обычные `INFO` в группы не входят.

`query.skipped_lines` и `text_lines` — строки не в JSON. Их нет в группах. Если у файла `json_lines` равен 0 и `text_lines` больше 0, канал ещё в старом текстовом виде: так и написать, не считать это отсутствием ошибок.

`query.truncated` и `truncation_reason` — сводка неполная. При `scan_limit` счётчики могут быть меньше фактических.

Идентификаторы из `samples` можно использовать только чтобы найти место в коде. В ответ не переносить `agent_id`, `user_id`, `task_id`, `loop_story_id`, коды объектов, номера групп и фамилии. `request_id` в ответ не копировать; при необходимости отдельным запуском добавить `--request=<id>` и разобрать `query.events`.

## Как решить, ошибка ли это кода

Разобрать каждый элемент `groups`. Пока список не прочитан, промпт не писать. Если канал в `download_errors`, про него не писать, что ошибок не было.

Для каждой группы:

1. Прочитать `message`, `event_name`, `exception_class`, `level` и поля примера.
2. Найти в репозитории код, который пишет этот текст.
3. По коду решить, верно ли ведёт себя программа. Сбой — проглоченная ошибка, повтор без конца, задача закрыта успехом, падение на обычном ответе внешнего сервиса, работа отложена не тем способом.
4. Если код при ошибке отодвигает работу на долгий срок по образцу другого пропуска, этот срок не копировать. Временный сбой повторить в том же запуске. Когда попытки кончились, работу сделанной не помечать и срок не отодвигать.
5. Если это только внешний отказ и код уже обрабатывает его верно, в промпт кода группу не включать.
6. Если по коду вывод сделать нельзя, группа всё равно входит в промпт: условие, место записи и какое поведение проверить.

Одинаковый `fingerprint` уже схлопнут. Разные отпечатки — разные пункты.

## Ответ

Коротко, по-русски. Сначала человек, в конце один промпт. Код по этой команде не править.

Человеку: интервал; какие каналы прочитаны и сколько в них JSON-строк; каналы со старым текстом; `missing_files`; `download_errors`, если скачивание сорвалось; `truncated`; каждая группа с уровнем, числом и текстом; какие из них становятся правкой кода. Если групп нет и старого текста нет — написать «Ошибок не было».

Промпт один на все сбои кода и стоит последним блоком ответа, чтобы его можно было скопировать целиком. Если сбоя кода нет, блок не писать. Внутри блока нет префиксов `>` и нет вложенных ограждений. В пункте: условие, файлы и методы, текущее поведение, нужное поведение, что не менять, тест Pest на условие, не на строку базы.

```text
Исправь ошибки в коде. Ниже только неправильное поведение, без журнала и без записей базы.

1. Ошибка: при каком условии возникает.
   Где: файлы, классы и методы.
   Сейчас: что делает код.
   Нужно: какое поведение записать.
   Не менять: что уже верно.
   Проверка: тест Pest на условие ошибки, не на строку базы.

Сделай все пункты. Соседние сценарии не трогай.
```
